# Project 01 — Nmap Reconnaissance Detection & Triage

A home SOC lab exercise simulating a network reconnaissance attack 
and observing how Security Onion detects and responds to it.

## What I Did

Ran three Nmap scans from Kali Linux against a Metasploitable2 target 
and analyzed the alerts generated by Security Onion.

- **SYN scan** (`-sS`): identified 23 open ports
- **Version detection** (`-sV`): fingerprinted service versions on each port
- **UDP scan** (`-sU`): probed common UDP services

## What Security Onion Detected

52 alert events across 17 distinct Suricata rules. The standout finding: 
Suricata fingerprinted the Nmap Scripting Engine from its HTTP user-agent 
string — identifying the exact tool in use before any exploitation attempt.

## Detection Limits — Slow Scan Note

Repeating the SYN scan with a 1-second probe delay (`--scan-delay 1s`) 
dropped alerts from 52 down to 4. All rate-based and user-agent rules 
were evaded; only port-specific signatures for MySQL, PostgreSQL, MSSQL, 
and Oracle fired. Signature-based detection alone has clear limits against 
a patient attacker.

## Tools Used

- Nmap
- Security Onion 2.4.211
- Suricata
- Zeek
